# 项目前端开发规范

## 1. 技术范围
前端使用 HTML、CSS、原生 JavaScript、Jinja2 模板和 ECharts。项目不引入 React、Vue、TypeScript 或复杂状态管理框架。

## 2. 页面结构
- 首页为演唱会数据分析看板。
- 页面包含筛选条件、核心统计数字、演唱会信息列表、推荐结果和图表区域。
- 图表包括城市分布、票价区间、评论数量变化、用户地区、关键词词云和情感倾向。
- 页面数据由 Flask 查询后传给模板，JavaScript 负责图表初始化、筛选刷新和推荐列表展示。
- 管理后台包含登录页、数据导入页、任务操作页和运行记录页。

## 3. 登录和后台交互
- 公开看板不要求登录。
- 管理员进入后台前必须完成登录，登录失败显示明确提示。
- 管理操作使用清晰的表单和确认信息，导入文件前显示文件名、字段和记录数量。
- 后台不提供公开注册、复杂角色切换和无关的用户社交功能。

## 4. 推荐交互
- 推荐页面支持城市、价格范围、时间范围和售票状态筛选。
- 推荐列表显示演唱会名称、城市、时间、价格、售票状态和推荐分数。
- 推荐分数用于解释排序，不显示为预测概率。
- 没有符合条件的演唱会时显示明确的空状态。

## 5. 图表约定
- 图表标题、坐标轴名称、图例和单位必须清楚。
- 颜色用于区分数据类别，不把颜色本身当作分析结论。
- 词云仅展示高频词，不把词云大小解释为严格的因果关系。
- ECharts 配置放在 `app/static/js/`，模板只保留容器和必要数据。

## 6. 明确不做
不制作营销型首页，不增加支付、社交、移动端和复杂运营页面。页面重点是信息查询、简单推荐、管理员维护和图表阅读，风格简洁、清晰，适合项目运行和验收截图。
