# 项目后端开发规范

## 1. 项目范围
本项目是基于 Python 的演唱会数据分析与可视化系统，后端负责数据查询、条件筛选、管理员登录、基础管理操作、推荐结果计算和页面数据组织。数据采集、清洗、分词和统计分析仍由 Python 脚本完成，Flask 不直接执行复杂爬虫。

## 2. 目录约定
计划采用以下轻量结构：

```text
app/
  routes.py           公开看板路由
  auth.py             管理员登录和退出
  admin_routes.py     管理后台路由
  models.py           SQLAlchemy ORM 模型
  recommend.py        规则型推荐函数
  templates/          Jinja2 页面模板
  static/             CSS、JavaScript 和图表资源
scripts/              采集、清洗、分词和统计脚本
data/raw/             原始 CSV 或 JSON 快照
data/cleaned/         清洗后的中间数据
data/dictionary/      停用词和自定义情感词典
tests/                解析、清洗、登录、ORM 和接口测试
docs/                 技术实施文档
```

## 3. 数据库和 ORM
- 使用 MySQL 保存规范化后的演唱会、票价、评论、统计结果和管理员数据。
- 使用 Flask-SQLAlchemy/SQLAlchemy 建立 `ConcertInfo`、`TicketPriceDetail`、`CommentInfo`、`AnalysisResult` 和 `AdminUser` 模型。
- 表名和字段名使用小写下划线命名，模型字段与数据库字段一一对应。
- 页面和后台使用 ORM 查询，不在路由中拼接 SQL；采集脚本可以继续使用 CSV 批量导入。
- 管理员密码只保存哈希值，不保存明文。
- 原始快照不覆盖，按采集批次保存，便于复查数据来源。

## 4. 数据处理约定
- 字段清洗放在 Python 采集/分析脚本中，不放在 HTML 模板中。
- 票价同时保留原始文本和解析后的最低价、最高价；解析失败时保留原文并记录异常。
- 去重优先使用来源记录编号；没有编号时使用演唱会名称、城市、演出时间和场馆组合判断。
- 评论清洗只删除无意义空白、HTML 标签和明显无效字符，不擅自改写原文。
- 关键词统计使用中文分词、停用词过滤和词频统计；SnowNLP 结果只作探索性展示。

## 5. 登录、后台和推荐
- 使用 Flask-Login 处理管理员会话；未登录用户只能访问公开看板。
- 管理后台只提供 CSV 导入、分析任务触发、运行记录查看和基础词典维护，不提供公开注册和复杂角色体系。
- 推荐功能使用规则函数，根据城市、价格范围、时间、售票状态、评论数量和点赞数计算简单排序分数。
- 推荐结果必须标明为规则排序结果，不宣称个性化准确率，不引入复杂机器学习模型。

## 6. 错误与日志
- 单条异常数据不能导致整批数据静默丢失，应记录异常原因和原始值。
- 采集、清洗、导入和分析脚本输出开始时间、结束时间、输入条数、成功条数、失败条数和异常文件路径。
- 登录失败、导入失败、ORM 查询失败和推荐查询失败都返回可理解的错误提示，不显示密码、数据库连接信息或完整堆栈。
